NYC Taxi & Traffic Database Design

A PostgreSQL design (physical schema) for loading the two Parquet outputs of download_and_preprocess_taxi_(KV).ipynb and serving the engineered features. It is a proposal, not something run against a database.

Schema overview

Blue = fact tables, grey = dimensions, amber = derived views (dashed). traffic_observation has composite PK (link_id, data_as_of) and FK link_id.

Design decisions

  • Star-style split. Trips and traffic readings are fact tables. Zone, payment type and traffic link are dimensions. The Parquet traffic_observations repeats borough, link_name and link_points on every reading, so those move to traffic_link_dim.
  • Derived features are generated columns. duration_minutes, profitability_index, tip_percent and good_tip are computed by the database, so they cannot drift from the raw columns. Division by zero yields NULL via NULLIF.
  • Monthly range partitions on pickup_ts. The data arrives monthly (about 3.4M rows each) and queries are time-bounded. Partitioned tables need the partition key in the PK, hence (trip_id, pickup_ts).
  • Zone aggregates are views. They are cheap to recompute; switch to materialized views if the full history grows large.
  • Money as numeric(10,2), not float, to avoid rounding drift in sums.

DDL

-- Dimensions
CREATE TABLE payment_type_dim (
  payment_type_id smallint PRIMARY KEY,
  description     text NOT NULL
);
INSERT INTO payment_type_dim VALUES
  (0,'Flex fare'),(1,'Credit card'),(2,'Cash'),(3,'No charge'),
  (4,'Dispute'),(5,'Unknown'),(6,'Voided');

CREATE TABLE taxi_zone_dim (
  location_id  smallint PRIMARY KEY CHECK (location_id BETWEEN 1 AND 263),
  zone         text NOT NULL,
  borough      text NOT NULL,
  service_zone text
);

CREATE TABLE traffic_link_dim (
  link_id     bigint PRIMARY KEY,
  borough     text,
  link_name   text,
  link_points text            -- space-separated "lat,lon" polyline
);

-- Facts
CREATE TABLE taxi_trip (
  trip_id         bigint GENERATED ALWAYS AS IDENTITY,
  pickup_ts       timestamp NOT NULL,
  dropoff_ts      timestamp NOT NULL,
  pu_location_id  smallint  NOT NULL REFERENCES taxi_zone_dim,
  do_location_id  smallint  NOT NULL REFERENCES taxi_zone_dim,
  trip_distance   numeric(6,2)  NOT NULL CHECK (trip_distance > 0 AND trip_distance <= 100),
  fare_amount     numeric(10,2) NOT NULL CHECK (fare_amount  >= 0),
  tip_amount      numeric(10,2) NOT NULL CHECK (tip_amount   >= 0),
  tolls_amount    numeric(10,2) NOT NULL CHECK (tolls_amount >= 0),
  total_amount    numeric(10,2) NOT NULL CHECK (total_amount >= 0),
  payment_type_id smallint REFERENCES payment_type_dim,   -- NULL if malformed
  -- engineered features
  duration_minutes numeric GENERATED ALWAYS AS
    (EXTRACT(EPOCH FROM dropoff_ts - pickup_ts) / 60) STORED,
  profitability_index numeric GENERATED ALWAYS AS
    ((fare_amount + tip_amount - tolls_amount)
      / NULLIF(EXTRACT(EPOCH FROM dropoff_ts - pickup_ts) / 60, 0)) STORED,
  tip_percent numeric GENERATED ALWAYS AS
    (tip_amount / NULLIF(fare_amount, 0)) STORED,
  good_tip smallint GENERATED ALWAYS AS
    (CASE WHEN tip_amount > 0.2 * fare_amount THEN 1 ELSE 0 END) STORED,
  PRIMARY KEY (trip_id, pickup_ts),
  CHECK (dropoff_ts > pickup_ts)
) PARTITION BY RANGE (pickup_ts);

CREATE TABLE taxi_trip_2026_08 PARTITION OF taxi_trip
  FOR VALUES FROM ('2026-08-01') TO ('2026-09-01');
CREATE TABLE taxi_trip_2026_09 PARTITION OF taxi_trip
  FOR VALUES FROM ('2026-09-01') TO ('2026-10-01');

CREATE TABLE traffic_observation (
  link_id     bigint    NOT NULL REFERENCES traffic_link_dim,
  data_as_of  timestamp NOT NULL,
  speed       numeric(6,2) CHECK (speed >= 0),   -- mph, may be NULL
  travel_time numeric(8,1) CHECK (travel_time >= 0), -- seconds, may be NULL
  PRIMARY KEY (link_id, data_as_of),
  CHECK (speed IS NOT NULL OR travel_time IS NOT NULL)
);

-- Zone-level tip propensity
CREATE VIEW zone_tip_pickup_v AS
  SELECT pu_location_id AS location_id, 100.0 * avg(good_tip) AS good_tip_percentage
  FROM taxi_trip GROUP BY pu_location_id;

CREATE VIEW zone_tip_dropoff_v AS
  SELECT do_location_id AS location_id, 100.0 * avg(good_tip) AS good_tip_percentage
  FROM taxi_trip GROUP BY do_location_id;

Loading from the notebook output

  1. Load taxi_zone_dim from the TLC zone lookup CSV (not produced by the notebook).
  2. Load traffic_link_dim from the distinct (link_id, borough, link_name, link_points) rows of traffic_observations.parquet, keeping the latest per link.
  3. COPY the Parquet columns (exported to CSV) into taxi_trip and traffic_observation. Generated columns fill themselves, so the notebook's cells 19–21 are no longer needed for loading.

Open points

  • The notebook's good_tip is tip_percent > 0.2; in SQL a zero fare gives 0 > 0, which is false and so 0, the same as the notebook's NaN case.
  • link_id is a string in the Parquet. It is modelled as bigint because the sample values are numeric; use text if non-numeric IDs appear.
  • A traffic-to-zone mapping table (link_id → location_id) is not included, since the notebook does no spatial join.
